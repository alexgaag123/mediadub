# pyannote Community‑1

[Все эксперименты](../README.md)

**Задача.** Проверить, можно ли улучшить назначение голосов в S01E01 «Любовь, смерть и роботы», сохранив слова и таймкоды одного прогона Parakeet v3.

## Методика

1. Подаём в Community‑1 выделенный голос MediaDub `vocals.wav`, сведённый в моно 16 кГц. На выходе два варианта интервалов. В обычном допускается одновременная речь, в эксклюзивном в каждый момент остаётся один голос. [Карточка модели](https://huggingface.co/pyannote/speaker-diarization-community-1)
2. Назначаем интервалы тем же словам v3 по пересечению. При слабом или неоднозначном пересечении ставим `?`. Для HTML сопоставляем ID Community‑1 и MediaDub по длительности общих слов.
3. Сравниваем оба варианта и отдельно проверяем сглаживание коротких переключений A → B → A. Отчёт сохраняет исходный ID каждого сглаженного слова.

**Наблюдение.** При прослушивании были ложные переключения внутри одной фразы и слова без ID. Сглаживание улучшало отдельные места, но по первой серии решили оставить MediaDub. Расхождение ID в отчёте показывает, где модели разошлись. Чтобы определить, какая из них права, нужен эталон.

## Запуск

Нужны FFmpeg, готовые `source.json` и `v3.json` из [эксперимента Parakeet](../parakeet/README.md), а также окружение с `pyannote.audio` 4.x и PyTorch для выбранного устройства. Прими условия на странице Community‑1 и войди в Hugging Face или введи токен чтения по скрытому запросу скрипта. Для запуска без CUDA укажи `--device cpu`.

```bash
.envs/pyannote/bin/python -m experiments.pyannote_community1.run_pyannote_community1 --episode S01E01 --smooth
xdg-open out/ldr_pyannote/S01E01/comparison_regular.html
```

При готовых `turns.json` и `turns_exclusive.json` флаг `--compare-only` пересобирает HTML без повторной диаризации.
